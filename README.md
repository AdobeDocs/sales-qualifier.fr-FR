# Contribuer à la documentation

Nous acceptons les contributions des membres de la communauté et des employés d’Adobe.

## Code de conduite open source d’Adobe

Ce projet respecte le code de conduite d’[Adobe Open Source](code-of-conduct.md) ou
le code de conduite de la Fondation [.NET](https://dotnetfoundation.org/code-of-conduct).
Pour plus d’informations, voir [Contribution](contributing.md).

## Comment contribuer au contenu Adobe

Si vous n’êtes pas employé d’Adobe, vous pouvez envoyer une contribution de la communauté. L’équipe de documentation examine les contributions dans le référentiel public et synchronise les modifications approuvées avec les systèmes internes Adobe.

Si vous êtes un employé d’Adobe, contribuez directement au [référentiel GitHub d’Adobe privé](https://git.corp.adobe.com/AdobeDocs/). Pour plus d’informations, consultez le guide de création d’Adobe Experience League pour les employés d’Adobe.

## Contributeurs et contributrices externes

### Modifications mineures

Si vous contribuez à une mise à jour mineure, procédez comme suit :

1. Accédez à la rubrique à modifier.
1. Dans le **Ce contenu a-t-il été utile ?** Dans la bannière située au bas de la page, sélectionnez **Options de commentaires détaillées**.
1. Sélectionnez **Suggérer une modification** et envoyez une requête de tirage (PR) avec vos modifications.

   Pour plus d’informations[&#128279;](https://experienceleague.adobe.com/en/docs/contributor/contributor-guide/introduction) consultez le guide du contributeur aux documents Adobe  .

Les corrections mineures ou les clarifications que vous soumettez pour la documentation et les exemples de code dans ce référentiel sont régies par les conditions d’utilisation d’Adobe.

### Changements majeurs et nouveaux sujets

Pour créer une rubrique ou proposer une modification majeure, soumettez un problème à partir de l’onglet **Problèmes** dans le référentiel Git approprié. Un membre de l’équipe de documentation travaille avec vous pour convenir d’un plan et publier la révision.

>[!NOTE]
>
>Si vous soumettez des modifications importantes de la documentation ou du code, la demande d’extraction vous invite à remplir un contrat de licence du contributeur en ligne (CLA). Renseignez le CLA avant que l’équipe de documentation ne examine votre demande d’extraction.

### Outils

Utilisez l’interface GitHub pour effectuer des modifications de base. Pour les contributions majeures, formez le référentiel.

Pour plus d’informations[&#128279;](https://experienceleague.adobe.com/en/docs/contributor/contributor-guide/introduction) consultez le guide du contributeur aux documents Adobe .

## Contributeurs et contributrices internes

Si vous êtes rédacteur technique, responsable de programme ou développeur de produits Adobe et que vous créez des articles techniques, utilisez le [référentiel privé](https://git.corp.adobe.com/AdobeDocs).

## Formater votre rubrique

Les articles de ce référentiel utilisent GitHub Flavored Markdown. Pour obtenir de l’aide, consultez les éléments suivants :

* [Concepts de base de Markdown](https://help.github.com/articles/getting-started-with-writing-and-formatting-on-github/)
* [Aide-mémoire imprimable Markdown](https://guides.github.com/pdfs/markdown-cheatsheet-online.pdf)

## Étiquettes

Le référentiel public attribue automatiquement des libellés aux requêtes d’extraction :

* **Modification envoyée à l’auteur** : l’auteur a été informé de la demande d’extraction en attente.
* **ready-to-merge** : la demande de tirage est prête pour la révision.
